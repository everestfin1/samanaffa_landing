Vue d’ensemble

Sama Naffa propose deux entrées principales pour les utilisateurs : la création de compte (parcours guidé en 6 étapes visibles) et la connexion pour les comptes déjà enregistrés.

1 · Nouveau client

Simulation d’épargne → téléphone & OTP → profil & dépôt → vérification d’identité (Didit) → portail.

/onboarding

2 · Client existant

Numéro de téléphone → code SMS à 6 chiffres → tableau de bord portail.

/login

Sécurité : le message après demande de code de connexion est volontairement générique (« si ce numéro est enregistré… ») pour ne pas révéler si un compte existe.

  1. T0 — Simulateur. L’utilisateur choisit un objectif d’épargne (maison, études, etc.), un montant mensuel et une durée. Résultat affiché pour motiver la suite.
  2. T1 — Téléphone & vérification. Saisie du numéro (format international), envoi d’un code OTP par SMS, validation. Création du compte utilisateur et connexion automatique via jeton serveur sécurisé (pas de mot de passe).
  3. T2 — Prénom. Collecte du prénom pour personnaliser l’expérience.
  4. T3 — Questionnaire (3 questions). Situation, capacité d’épargne, expérience → recommandation de formule (ex. Formule Libre).
  5. T4 — Intention de dépôt. Montant du premier dépôt et choix du portefeuille mobile (InTouch). Une intention de transaction est enregistrée ; le paiement réel intervient après validation KYC.
  6. T5 — Vérification d’identité (Didit). Parcours Didit : document d’identité et selfie. Sur ordinateur : modale SDK ; sur mobile : redirection. Statuts : en cours, approuvé, refusé (avec nouvelle tentative possible).
  7. T6 — Écran de succès. Félicitations, rappel du dépôt et de la formule. Bouton vers le portail client (/portal/dashboard).
Après T1 : si la connexion automatique échoue, redirection vers /login?callbackUrl=/onboarding pour reprendre avec le même numéro.

Parcours 2 — Connexion (client existant)

Réservé aux numéros déjà enregistrés lors de l’onboarding. Aucun mot de passe.

Étape A — Saisie du numéro

Validation du format (ex. +221 77 …). Bouton « Recevoir mon code ».

Étape B — Envoi OTP

SMS avec code à 6 chiffres (valide 5 min). Message générique si le compte existe.

Étape C — Saisie du code

Vérification du code. Aide affichée si aucun SMS (« même numéro qu’à l’inscription », lien création de compte).

Étape D — Portail

Redirection vers le tableau de bord ou l’URL demandée (callbackUrl).

Environnement de test : avec MOCK_OTP=true, aucun SMS réel ; le code de test s’affiche en local pour les numéros enregistrés. Numéro inconnu : message explicite en dev uniquement.

Après inscription — Portail client

Une fois connecté, l’utilisateur accède à l’espace sécurisé /portal.

  1. Tableau de bord. Vue d’ensemble des comptes (Sama Naffa, produits liés selon configuration).
  2. Complétion du profil (si nécessaire). Modal : email, acceptation des conditions, signature — avant certaines actions.
  3. Sama Naffa — dépôt. Après KYC approuvé : confirmation du dépôt initié en T4 via InTouch (lien de paiement / instructions).
  4. Profil & KYC. Consultation du statut ; relance Didit depuis le profil si besoin.
  5. Notifications. Mises à jour KYC, transactions, etc.
  6. Déconnexion / session. JWT avec expiration ; déconnexion après inactivité (~15 min) dans le portail.
Hors scope de ce document : parcours admin (/admin), landing marketing APE/PEE, et ancienne inscription /register (redirige vers /onboarding).
